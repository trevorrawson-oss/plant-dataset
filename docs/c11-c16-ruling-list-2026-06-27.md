## C11 -- the two evasion shapes, and why each needs a ruling

A25 (`register_completeness`) HALTs on a novel PROSE field. Today it only flags prose-shaped
STRINGS (len >= 25 or sentence punctuation), so a novel field slips if its value is a short string,
a non-string, or under a key that is already excluded. The fix is NOT "flag any unruled key" (that
floods): the 18 carry **49 legit unruled short-string keys** + **202 legit unruled non-string keys**.
We rule those, then tighten A25 to "flag ANY unruled STRING key regardless of length."

### Part 2 -- the 202 non-string unruled keys (proposed BLANKET ruling, then (b) closes)

These are not prose and not register fields -- they are the numeric/structural schema:
- 45 are tip / consumer-compound `list[obj]` (growth_stages, pests, diseases, notifications, tips_by_stage, ...)
- 40 are numeric scalars (chill_hours_required, min_pot_gallons, days_to_maturity_mid, ...)
- 20 are `[lo,hi]` ranges (spacing_inches, germination_temp_f, days_to_maturity, ...)
- 18 are id/token lists (sources, container_suitable_varieties, preferred_texture_core, ...)
- 79 are other dict/mixed structures (regions, weather_triggers, schedule_by_stage, ...)

**Proposed ruling:** `register_completeness` (A25) governs PROSE (strings) ONLY, by design -- a novel
NON-STRING field is the domain of the SHAPE / archetype gates (display_readiness A20, the calendar
derivers A4/A11/A14/A16, compound-population A12, photoperiod A9, ...), not the prose roster. So we
**scope A25 explicitly to strings** and do not individually rule these 202. (A novel non-string field
that no shape gate covers would be caught by C7's planned numeric-sanity + cross-consistency gates --
the truth-layer thread -- not by A25.)
  **[ accept blanket ruling ✓ / ✗ -- if ✗, which non-string keys do you want A25 to police? ]**

### Then (c) -- the backend-key dash-laundering (`summary`/`claim`/`note`)

`summary`/`claim`/`note` are excluded because they are legit backend keys; a bot hiding grower
content (incl. a forbidden `--`) under them exploits the exemption. This is path-sensitive (a legit
backend `note` may carry `--`). **Proposed:** once Parts 1-2 land, A25 flags any unruled STRING key
regardless of length, AND we add a narrow rule: a string under one of {`summary`,`claim`,`note`}
that appears OUTSIDE a known-backend subtree (verification_status / provenance / *_admission / audit
leaves) is flagged for review. Needs a 0-FP check across the 18 first. **[ pursue ✓ / defer ✗ ]**

## C16 -- dual-voice by omission: the real decision is only 6 field-types

A `_seasoned` field with no `_beginner` sibling is counted SP (legit) per the locked "Presence IS the

`frost_risk_note_seasoned`, `source_note_seasoned`, `zone_coverage_note_seasoned`,
`microclimate_note_seasoned`, `count_note_seasoned` -- all already `is_backend` (own-voice reasoning /
audit prose, correctly seasoned-only, no beginner copy owed). **No action on those 179.**

The genuine "should this be dual-register (CP) or legitimately SP?" decision is **6 field-types**:
